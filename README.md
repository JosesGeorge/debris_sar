# INZORA SONAR INTELLIGENCE

> **⚠ SIMULATION MODE** — All sonar data, target detections, acoustic signals, and 3D models are synthetically generated by a JavaScript simulation engine. This system does not connect to real sonar hardware in its current form.

Premium underwater marine debris detection and SONAR visualization dashboard. Built as a frontend-only React+TypeScript+Vite application deployable as a static website on Vercel.

---

## Features

- **360° Sonar Radar** — Rotating sweep with range rings, angular markings, and live target plotting
- **5 Debris Scenarios** — Plastic waste field, mixed debris, ghost nets, dynamic tracking, clean seabed
- **8 Debris Categories** — Plastic bottles, bags, aluminium cans, fishing nets, tires, metal scrap, unknown
- **Interactive 3D Wireframe Viewer** — Three.js representative models for each debris type (drag to rotate, scroll to zoom)
- **Acoustic Signal Waveform** — Simulated echo visualization from the sonar engine
- **Real-time Statistics** — All metrics derived from live simulation state
- **Scan Controls** — Start, Pause, Resume, Reset, Change Scenario, Change Range, Clear Targets
- **Event Log** — System activity stream

## Local Development

### Prerequisites
- Node.js 18+ 
- npm 9+

### Setup

```bash
# Clone the repository
git clone https://github.com/JosesGeorge/debris_sar.git
cd debris_sar

# Install dependencies
npm install

# Start the development server
npm run dev
```

The app opens at **http://localhost:3000**

No backend server, database, or environment variables required.

## Vercel Deployment

### Option A — Deploy from GitHub (Recommended)

1. Push this repository to GitHub
2. Go to [vercel.com](https://vercel.com) → **New Project**
3. Import the GitHub repository
4. Vercel auto-detects the Vite framework — confirm settings:
   - **Framework Preset**: Vite
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
5. Click **Deploy**

No environment variables required.

### Option B — Vercel CLI

```bash
npm install -g vercel
vercel
```

## Simulation Architecture

The simulation engine runs entirely in the browser:

```
SonarSimulator (sonarSimulator.ts)
  ├── Loads scenario targets from scenarios.ts
  ├── Updates target positions (dynamic mode)
  ├── Drifts confidence and signal strength
  ├── Generates acoustic echo buffer (Float32Array)
  └── Calls React callbacks → triggers re-render

React State (App.tsx)
  ├── targets[] → SonarRadar (canvas blips)
  ├── targets[] → InzoraHUD (target list, stats)
  ├── selectedId → WireframeViewer (3D model)
  └── acousticData → AcousticWaveform (canvas waveform)
```

## Future Hardware Integration

The simulation is designed to be hardware-ready. To replace synthetic data with real sonar:

1. **Implement a data provider** that produces `SonarTarget[]` objects in the same format
2. **Replace `SonarSimulator`** with a hardware adapter (WebSocket, REST polling, or Web Serial API)
3. **Compatible hardware paths**:
   - Imaging SONAR (BlueView, Gemini) → WebSocket stream
   - Side-scan SONAR → REST API
   - Raspberry Pi / ESP32 acoustic sensor → Web Serial API
   - Python signal processing → REST or WebSocket bridge

The `SonarTarget` interface is the stable integration boundary.

## Known Limitations

- All data is synthetic — not suitable for actual marine monitoring
- 3D models are representative shapes, not acoustic reconstructions
- No persistent storage — data resets on page reload
- No multi-user or network sharing
- Classification is deterministic rule-based, not ML-based
